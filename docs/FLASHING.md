# 刷写与首次启动

## 适用范围

本说明只适用于 README 默认设备清单中、且已经生成对应文件名的 EchoWrt 镜像。DoorNet、LubanCat 与 Hinlink 等尚未完成 25.12 移植的设备不能套用这些镜像或旧项目教程。

## 刷写前检查

1. 核对设备完整型号、硬件版本、内存与启动介质。
2. 阅读产物中的 `BUILD_INFO.txt`，确认源码分支、提交和构建 profile。
3. 下载 `FIRMWARE_SHA256SUMS` 和对应镜像，在固件目录执行 `sha256sum --ignore-missing -c FIRMWARE_SHA256SUMS`；已下载的镜像必须显示 `OK`，且不能出现校验失败。下载全部镜像时可以执行 `sha256sum -c FIRMWARE_SHA256SUMS`。
4. 备份当前配置，并准备串口、Maskrom 或厂商恢复工具等可用的救砖路径。
5. 首次测试优先使用可移除的 SD 卡，不要直接覆盖仍可启动的 eMMC。

## 写入镜像

先解压对应设备的 `.img.gz`，再使用受信任的图形化镜像写入工具。写入前通过系统磁盘管理器核对目标盘容量和设备名；拔掉无关移动磁盘可以降低误写风险。

本项目不提供把固定 `/dev/mmcblk*` 或 `/dev/sd*` 路径直接写死的命令。设备名判断错误会立即覆盖其他磁盘，而不同 Rockchip 板卡的启动介质编号并不一致。

## 首次启动

- 只连接可信 LAN，等待设备完成首次扩容与启动。
- 打开 `http://192.168.8.1/`，用户名为 `root`。
- 固件不预置密码；首次登录后立即设置强密码。
- 设置密码并核对防火墙前，不要把管理口或 SSH 暴露到公网。

## 验证与回退

按 [维护与发布约定](MAINTENANCE.md) 的实机冒烟清单检查启动日志、网口、存储和重启。发现设备型号不符、持续内核异常或网口映射错误时停止升级测试，保留串口日志和三份构建追溯文件，并使用预先确认的恢复路径回退。
